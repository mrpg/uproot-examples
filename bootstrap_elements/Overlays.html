Overlays appear on top of the page. Modals demand attention and block the page until they are closed; tooltips, popovers, and toasts add information without interrupting. Modals and dropdowns work with data-bs-* attributes alone, whereas tooltips, popovers, and toasts need a line of JavaScript, which you find in the late block of this template.

Modals

A modal is a dialog window. In experiments, modals are useful for important notices, for asking participants to confirm a decision, and for reference material such as a payoff table. A modal consists of .modal > .modal-dialog > .modal-content, which contains a header, a body, and a footer. A button with data-bs-toggle="modal" and data-bs-target opens it; any element inside with data-bs-dismiss="modal" closes it, as do Esc and a click on the dark backdrop.

Key classes and attributes: .modal, .fade, .modal-dialog, .modal-content, .modal-header, .modal-title, .modal-body, .modal-footer, data-bs-toggle="modal", data-bs-dismiss="modal"

Static backdrop: participants must acknowledge

With data-bs-backdrop="static" and data-bs-keyboard="false", the modal ignores clicks on the backdrop and the Esc key. Participants can only close it with the buttons you provide, for example after reading an important notice.

Centered and scrollable

.modal-dialog-centered centers the dialog vertically. .modal-dialog-scrollable keeps header and footer visible and scrolls only the body, which suits long texts like a consent form.

Sizes

Modals come in several widths. .modal-fullscreen-sm-down and similar classes make a modal fill the screen only below a breakpoint, which is often the best choice on phones.

Key classes (on .modal-dialog): .modal-sm, .modal-lg, .modal-xl, .modal-fullscreen, .modal-fullscreen-sm-down (also -md-, -lg-, …)

Opening modals with JavaScript, and listening to them

To open a modal from code, for instance when a timer expires or a live message arrives, use bootstrap.Modal.getOrCreateInstance(element).show(); .hide() closes it. Bootstrap fires events such as shown.bs.modal and hidden.bs.modal. The example uses them to measure how long the modal was open, which can serve as a rough measure of reading time.

uproot’s built-in modal

For a quick message, uproot provides uproot.alert(html), which shows a ready-made modal. It interprets its argument as HTML, so pass text that came from participants through uproot.escape() first.

Tooltips

A tooltip is a short text that appears while the mouse pointer rests on an element or the element has keyboard focus. Tooltips suit definitions of terms. Put the text into data-bs-title, add data-bs-toggle="tooltip", and initialize all tooltips once (see the late block). An element that is not focusable by default, such as a <span>, needs tabindex="0" for keyboard users.

Attributes: data-bs-toggle="tooltip", data-bs-title, data-bs-placement (top, right, bottom, left)

Pitfall. Phones have no mouse pointer, so many participants will never see a tooltip. Do not put essential information into tooltips; use a popover or visible text instead.

Popovers

A popover is a larger tooltip with an optional title that opens on click, which works on phones, too. With data-bs-trigger="focus", it closes on the next click anywhere. Like tooltips, popovers must be initialized. (uproot uses popovers for the values of its sliders.)

Attributes: data-bs-toggle="popover", data-bs-title, data-bs-content, data-bs-placement, data-bs-trigger

Toasts

Toasts are small notifications in a corner of the screen that disappear by themselves. They inform without interrupting: “Your partner has made a decision”, “Your offer was accepted”. Place them in a fixed .toast-container and show them with bootstrap.Toast.getOrCreateInstance(element).show(). In a live experiment, you would call this from a handler that receives messages from the server (see the notifications app).

Key classes and attributes: .toast-container, .toast, .toast-header, .toast-body, data-bs-delay, data-bs-autohide

Dropdowns

A dropdown is a menu that opens from a button. It is better suited to actions than to answers: to let participants choose a value, use a SelectField or a RadioField (see the input_elements app), which uproot validates and stores. Items should be buttons with type="button".

Key classes and attributes: .dropdown, .dropdown-toggle, .dropdown-menu, .dropdown-item, .dropdown-header, .dropdown-divider, data-bs-toggle="dropdown"
