Overlays appear on top of the page. Dialogs demand attention and block the page until they are closed; tooltips, popovers, toasts, and menus add information or options without interrupting. Dialogs, tooltips, popovers, and menus work with data-bs-* attributes alone. Toasts, and dialogs that should open without a click, need a line of JavaScript, which you find in the late block of this template.

Dialogs

A dialog is a window on top of the page. In experiments, dialogs are useful for important notices, for asking participants to confirm a decision, and for reference material such as a payoff table. A dialog is a native <dialog class="dialog"> element with a header, a body, and a footer. A button with data-bs-toggle="dialog" and data-bs-target opens it; any element inside with data-bs-dismiss="dialog" closes it, as do Esc and a click on the dimmed backdrop. While it is open, the browser keeps keyboard focus inside the dialog and the rest of the page cannot be used.

Key classes and attributes: <dialog class="dialog">, .dialog-header, .dialog-title, .dialog-body, .dialog-footer, data-bs-toggle="dialog", data-bs-dismiss="dialog"

Static backdrop: participants must acknowledge

With data-bs-backdrop="static" and data-bs-keyboard="false" on the <dialog>, it ignores clicks on the backdrop and the Esc key. Participants can only close it with the buttons you provide, for example after reading an important notice.

Scrollable dialogs

Dialogs open in the middle of the screen. .dialog-scrollable keeps header and footer visible and scrolls only the body, which suits long texts like a consent form.

Opening dialogs with JavaScript, and listening to them

To open a dialog from code, for instance when a timer expires or a live message arrives, import Dialog in a <script type="module"> and use Dialog.getOrCreateInstance(element).show(); .hide() closes it. Bootstrap fires events such as shown.bs.dialog and hidden.bs.dialog. The example uses them to measure how long the dialog was open, which can serve as a rough measure of reading time.

For a quick message, uproot provides uproot.alert(html), which shows a ready-made dialog. It interprets its argument as HTML, so pass text that came from participants through uproot.escape() first.

Tooltips

A tooltip is a short text that appears while the mouse pointer rests on an element or the element has keyboard focus. Tooltips suit definitions of terms. Put the text into data-bs-title and add data-bs-toggle="tooltip"; Bootstrap sets up the tooltip by itself. An element that is not focusable by default, such as a <span>, needs tabindex="0" for keyboard users. Tooltips stay open while the pointer is on the tooltip itself, and Esc closes them.

Attributes: data-bs-toggle="tooltip", data-bs-title, data-bs-placement (top, right, bottom, left)

Pitfall. Phones have no mouse pointer, so many participants will never see a tooltip. Do not put essential information into tooltips; use a popover or visible text instead.

Popovers

A popover is a larger tooltip with an optional title that opens on click, which works on phones, too. With data-bs-trigger="focus", it closes on the next click anywhere. Like tooltips, popovers set themselves up. (uproot uses popovers for the values of its sliders.)

Attributes: data-bs-toggle="popover", data-bs-title, data-bs-content, data-bs-placement, data-bs-trigger

Toasts

Toasts are small notifications in a corner of the screen that disappear by themselves. They inform without interrupting: “Your partner has made a decision”, “Your offer was accepted”. Place them in a fixed .toast-container and show them with Toast.getOrCreateInstance(element).show(). In a live experiment, you would call this from a handler that receives messages from the server (see the notifications app).

Key classes and attributes: .toast-container, .toast, .toast-header, .toast-body, data-bs-delay, data-bs-autohide

Menus

A menu opens from a button and lists actions. It is better suited to actions than to answers: to let participants choose a value, use a SelectField or a RadioField (see the input_elements app), which uproot validates and stores. The toggle button and the .menu are siblings; items should be buttons with type="button".

Key classes and attributes: data-bs-toggle="menu", .menu, .menu-item, .menu-header, .menu-divider, data-bs-placement
