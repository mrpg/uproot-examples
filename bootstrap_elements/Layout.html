Layout decides where things go on the screen. Bootstrap’s layout tools are mobile first: you describe the layout for small screens and then add changes for larger screens. This matters for online experiments, where many participants use phones. The light-blue boxes in this chapter (.wt-cell) only make the otherwise invisible columns visible.

Containers

A container centers content and limits its width. You rarely need to add one yourself: uproot already wraps the main, main2, and main3 blocks in a .container, whose maximum width grows with the screen. For content that should span the whole window, such as a colored band, use the main_full_width block and put a .container inside to keep its text aligned with the rest of the page:

{% raw %}{% block main_full_width %}
<div class="bg-subtle-primary py-7">
    <div class="container">Full-width band with aligned text</div>
</div>
{% endblock main_full_width %}{% endraw %}

Key classes: .container, .container-fluid (always full width), .md:container (full width below the md breakpoint)

The grid

The grid divides a row into twelve columns. Put columns (.col, .col-*) directly inside a .row. Columns with plain .col share the space equally; .col-4 takes four of twelve columns; .col-auto is only as wide as its content.

Key classes: .row, .col, .col-1 to .col-12, .col-auto

Responsive breakpoints

Put a breakpoint in front of a class, followed by a colon, to apply the class only from a certain screen width upwards. .col-12 .md:col-6 .lg:col-3 means: full width on phones, half width from tablets (md), and a quarter from laptops (lg). Resize your browser window to see the example below rearrange itself. Breakpoints work with most classes, not only with columns: .md:d-none, .lg:text-end, and so on. In the HTML, the colon is written as is: class="md:col-6".

Tip. Two options side by side on a laptop become two options stacked on a phone. Participants on phones may then see Option A long before Option B. If position matters for your design, test your pages on a phone (most browsers’ developer tools can simulate one).

Gutters

Gutters are the gaps between columns. Set them on the row with .g-0 to .g-12 (both directions), .gx-* (horizontal), or .gy-* (vertical, useful when columns wrap). The numbers follow the spacing scale explained below. .row-cols-* sets the number of columns per row on the row itself, which is handy for grids of cards.

Key classes: .g-*, .gx-*, .gy-*, .row-cols-*

Alignment, offsets, and order

Rows are flex containers, so they align columns with flexbox classes: .justify-content-* horizontally and .align-items-* vertically. .md:offset-2 leaves two columns empty, and .order-* changes the visual order.

Key classes: .justify-content-center, .align-items-center, .offset-*, .order-first, .order-last, .md:order-*

Pitfall. It is tempting to counterbalance the left/right position of options with .order-*. But screen readers and the Tab key follow the order in the HTML, not the visual order. Randomize the order in Python instead (see the randomize_pages and conjoint apps).

Flexbox and stacks

Not everything needs a grid. For a single line of items, use .d-flex with .gap-*; .ms-auto on an item pushes it (and everything after it) to the right. Stacks are shortcuts: .hstack is a horizontal, vertically centered flex row; .vstack a vertical one. .vr draws a vertical rule.

Key classes: .d-flex, .flex-wrap, .flex-column, .gap-*, .ms-auto, .hstack, .vstack, .vr

Stacks that respond to their container

Responsive stacks such as .sm:hstack do not look at the width of the window but at the width of the surrounding element. Mark that element with .stack-container. The stack then switches from vertical to horizontal once its container is at least as wide as the breakpoint (576 px for sm), so the same markup works in a narrow sidebar and in a wide main column. In the example, both stacks use the same classes, but only the one in the wider column turns horizontal (on a phone, neither does).

Spacing

Margin (m) and padding (p) classes follow one pattern: property, side, size. Sides are t (top), b (bottom), s (start, i.e., left), e (end, i.e., right), x (left and right), y (top and bottom), or nothing (all sides). Sizes go from 0 to 12 in fine steps; the most common ones are 3 (0.5rem), 5 (1rem), 7 (1.5rem), and 12 (3rem). The same scale applies to .gap-* and to gutters. .mx-auto centers a block with a set width.

Examples: .mt-5 (margin-top 1rem), .px-3 (horizontal padding 0.5rem), .mb-0, .p-7, .mx-auto

Pitfall. The spacing scale changed in Bootstrap 6: .mt-3 used to be 1rem and is now 0.5rem. When you copy markup written for Bootstrap 5, use 3 for 2, 5 for 3, 7 for 4, and 12 for 5 to keep the same spacing.

Sizing

Width classes set a width relative to the parent: .w-25, .w-50, .w-75, .w-100, and .w-auto. .w-1 to .w-12 set a fixed width from 1rem to 12rem, and .w-fit makes an element exactly as wide as its content. .max-w-100 prevents an element from becoming wider than its parent. Heights work the same with .h-*; .h-100 is useful to give cards in a row equal height.

Aspect ratios

Embedded videos and iframes do not scale on their own. Give them .ratio-16x9, .ratio-4x3, .ratio-1x1, or .ratio-21x9 (together with a width such as .w-100), and they keep their shape at every width. The example uses a placeholder instead of a real video to avoid loading external content.
