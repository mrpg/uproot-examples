How the guided tour works

The tour is not a library: it is about 300 lines in _static/tour.js and a few lines in _static/tour.css, without third-party code. Copy both files into your app’s _static folder to use it.

  • The spotlight is an empty box placed over the current element. Its huge box-shadow darkens everything else on the page.
  • The explanation uses the markup and classes of a Bootstrap popover (.popover, .popover-header, .popover-body, and .popover-arrow), but the tour positions it itself. Its Back, Next, and Done buttons are built as DOM elements, and all texts are inserted with textContent, so they are never interpreted as HTML.
  • Before anything moves, the tour works out where the page will scroll to and where the popover ends up: on the step’s placement if there is room, otherwise on the side with the most room, and always inside the window. Spotlight and popover then glide there together with a CSS transition (unless the participant prefers reduced motion).
  • While the tour runs, the rest of the page is inert: it can be neither clicked nor focused, and screen readers skip it. A click on the dimmed page ends the tour, as do the Esc key and the close button; ← and → navigate.
  • Steps whose element does not exist or is hidden (for example on a phone) are skipped.

A tour is a list of steps, each with a CSS selector, a title, a text, and optionally a placement. This page starts its tour with a button:

const steps = [
    {
        target: "#tour-options",
        title: "Make your choice",
        content: "Click on a card to select it.",
        placement: "top",  // Optional: "top", "right", "bottom", or "left"
    },
    // ...
];

I("start-tour").addEventListener("click", () => Tour.start(steps));

To start the tour automatically when the page loads, use uproot.onStart(() => Tour.start(steps)); instead. Keep in mind that it then starts again whenever the page is reloaded, for example after a failed validation.

How the confirmation works

The Submit decision button has type="button", so it does not submit anything by itself. Its click handler (in the late block) checks whether an option is selected. If not, it reveals the red callout by removing its hidden attribute. If so, it writes the name of the option into the dialog and opens it. The dialog’s Confirm button is uproot’s own Next button, placed with button_next(label=…). Because the <dialog> sits inside uproot’s form, this button submits the page as usual, and uproot validates and stores the field option.

Bootstrap 6 has no global bootstrap object. To use a component from JavaScript, import it in a <script type="module">, as this page does:

import { Dialog } from "bootstrap";

Dialog.getOrCreateInstance(I("confirm-dialog")).show();

Tip. The selectable cards are a pattern worth reusing: a <label class="card"> with a radio button inside, highlighted with the CSS selector :has(:checked). They remain real radio buttons, so they work with the keyboard (Tab and the arrow keys) and with screen readers. For plainer lists of options, Bootstrap’s .form-field-card does the same without custom CSS.
