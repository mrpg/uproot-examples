How the guided tour works

The tour is not a library: it is about 200 lines in _static/tour.js and a few lines in _static/tour.css, built entirely on Bootstrap. Copy both files into your app’s _static folder to use it.

  • The spotlight is an empty box placed over the current element. Its huge box-shadow darkens everything else on the page. A CSS transition lets it glide from step to step.
  • The explanation is a regular Bootstrap popover, attached to the spotlight and opened with trigger: "manual". Its Back, Next, and Done buttons are built as DOM elements, and all texts are inserted with textContent, so they are never interpreted as HTML.
  • A transparent backdrop catches clicks on the page, which end the tour. So do the Esc key and the close button; ← and → navigate.
  • Steps whose element does not exist or is hidden (for example on a phone) are skipped.

A tour is a list of steps, each with a CSS selector, a title, a text, and optionally a placement. This page starts its tour with a button:

const steps = [
    {
        target: "#tour-options",
        title: "Make your choice",
        content: "Click on a card to select it.",
        placement: "top",  // Optional: "top", "right", "bottom", "left", or "auto" (default)
    },
    // ...
];

I("start-tour").addEventListener("click", () => Tour.start(steps));

To start the tour automatically when the page loads, use uproot.onStart(() => Tour.start(steps)); instead. Keep in mind that it then starts again whenever the page is reloaded, for example after a failed validation.

How the confirmation works

The Submit decision button has type="button", so it does not submit anything by itself. Its click handler (in the late block) checks whether an option is selected. If not, it reveals the red callout. If so, it writes the name of the option into the modal and opens it. The modal’s Confirm button is uproot’s own Next button, placed with button_next(label=…). Because the modal sits inside uproot’s form, this button submits the page as usual, and uproot validates and stores the field option.

Tip. The selectable cards are a pattern worth reusing: a hidden radio button (.btn-check) followed by a <label> that looks like a card. They remain real radio buttons, so they work with the keyboard (Tab and the arrow keys) and with screen readers.
