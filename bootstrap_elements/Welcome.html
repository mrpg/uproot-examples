This app is a walkthrough of the user interface elements that Bootstrap provides, with a focus on what is useful in experiments: instructions, decision screens, feedback, and results. Every chapter explains when to use something, shows a live example, and names the classes involved. Open the template of any chapter (e.g., bootstrap_elements/Tables.html) to see the exact markup.

Use ← and → to navigate and Esc to end the tour.

What is available on every page

uproot loads the following on every page that extends Base.html. You do not need to add anything for these:

  • Bootstrap 5: CSS and JavaScript, including Popper (used for tooltips, popovers, and dropdowns). The version shown here is read live from bootstrap.Tooltip.VERSION.
  • Alpine.js for small bits of interactivity (see the counter_alpine app).
  • uproot’s stylesheet, which adds a few classes on top of Bootstrap, such as .callout, .btn-uproot, .text-uproot, .fw-500, and .w-fit-content. You will meet them throughout this walkthrough.
  • Bootstrap Icons ship with uproot but are not loaded automatically. One line in the head block is enough:
{% raw %}{% block head %}
<link rel="stylesheet" href="{{ internalstatic('vendor/bootstrap-icons/bootstrap-icons.min.css') }}">
{% endblock head %}{% endraw %}

Five rules for Bootstrap in uproot

  1. Every button needs type="button". The main block sits inside uproot’s <form>. A <button> without a type is a submit button and moves the participant to the next page. This is the most common mistake when copying examples from Bootstrap’s documentation.
  2. Put things in the right template block. Stylesheets and metadata go into head, visible content into main (or main_full_width for full-width bands), and scripts into late. The templating_and_typography app shows all blocks.
  3. Some components need one line of JavaScript. Collapse, accordions, tabs, modals, offcanvas panels, dropdowns, and carousels work through data-bs-* attributes alone. Tooltips, popovers, and toasts must be initialized explicitly (see the chapter on overlays).
  4. Prefer utility classes over custom CSS. Classes like .mt-3, .d-flex, or .text-center cover most needs. If you need your own CSS, put it into a file in your app’s _static folder and load it with appstatic(), as this app does with walkthrough.css.
  5. Do not rely on color alone. Some participants are color-blind or use screen readers. Pair colors with text or icons, and give icon-only controls a label. The chapters show how.
