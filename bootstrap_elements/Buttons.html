Buttons trigger actions: showing a hint, opening a dialog, or submitting a decision. In uproot, submitting the page is the job of the Next button, which uproot places for you. Every other button on a page must be told explicitly that it is not a submit button.

The one rule: type="button"

Everything in the main block is inside uproot’s <form>. In a form, a <button> without a type attribute is a submit button. Clicking it submits the page, which is almost never what you want for an extra button. Bootstrap’s documentation often omits the type, because its examples are not inside forms.

Pitfall. A <button class="btn btn-primary">Show hint</button> copied from the internet would submit this page. Links styled as buttons (<a class="btn">) do not submit, but they navigate away if they have an href.

Variants

A button’s color signals its role. Use one primary button per screen for the main action, a secondary or outline button for alternatives, and .btn-danger only for actions with serious consequences. uproot adds .btn-uproot and .btn-outline-uproot in its own purple.

Key classes: .btn with .btn-primary, .btn-secondary, .btn-success, .btn-danger, .btn-warning, .btn-info, .btn-light, .btn-dark, .btn-link, .btn-uproot; outline versions with .btn-outline-*

Sizes and states

Buttons come in three sizes, plus uproot’s extra small .btn-xs. A disabled attribute grays a button out and makes it unclickable, for example until a participant has read something. .active with aria-pressed="true" shows a button as pressed.

Key classes and attributes: .btn-lg, .btn-sm, .btn-xs (uproot), disabled, .active, aria-pressed

Buttons with icons

An icon before the label makes a button quicker to recognize. Icon-only buttons save space, but need an aria-label (or a .visually-hidden text) so that screen readers can announce them.

Full-width buttons and alignment

On phones, large touch targets are easier to hit. Wrap buttons in .d-grid to make them full width; .d-md-flex with .justify-content-md-end turns them back into normal buttons on larger screens. To arrange uproot’s own Next and Back buttons, see the button_placement app (this walkthrough uses button_next(label=…) in Chapter.html).

Key classes: .d-grid, .gap-2, .d-md-flex, .justify-content-md-end, .w-100

Button groups and toolbars

A button group joins related buttons into one control. Give it role="group" and an aria-label. Several groups form a toolbar.

Key classes: .btn-group, .btn-group-vertical, .btn-group-sm, .btn-group-lg, .btn-toolbar

Toggle buttons

Radio buttons and checkboxes can look like buttons: add .btn-check to the <input> and a .btn class to its <label>. Radios in a .btn-group form a segmented control, which is a compact way to switch between views.

Key classes: .btn-check on the input, .btn .btn-outline-* on the label

Selected view: table

Tip. uproot only saves inputs that belong to a field defined in Python, so these toggles are not stored. To store a choice made with toggle buttons, define a field (e.g., a RadioField) and give the inputs its name. The last chapter does exactly that with cards. For the standard ways to ask questions, see the input_elements app.

The close button

.btn-close draws a neutral “×”. Alerts, modals, toasts, and offcanvas panels use it to dismiss themselves. It has no text, so it always needs an aria-label.
