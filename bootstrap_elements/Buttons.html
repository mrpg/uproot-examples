Buttons trigger actions: showing a hint, opening a dialog, or submitting a decision. In uproot, submitting the page is the job of the Next button, which uproot places for you. Every other button on a page must be told explicitly that it is not a submit button.

The one rule: type="button"

Everything in the main block is inside uproot’s <form>. In a form, a <button> without a type attribute is a submit button. Clicking it submits the page, which is almost never what you want for an extra button. Bootstrap’s documentation often omits the type, because its examples are not inside forms.

Clicked 0 times, and you are still on this page.

Pitfall. A <button class="btn-solid theme-primary">Show hint</button> copied from the internet would submit this page. Links styled as buttons (<a class="btn-solid theme-primary">) do not submit, but they navigate away if they have an href.

Variants and colors

A button combines a variant, which sets its style, with a theme class, which sets its color. The variants range from loud to quiet: .btn-solid, .btn-outline, .btn-subtle, and .btn-text. The color signals the button’s role. Use one solid primary button per screen for the main action, quieter buttons for alternatives, and .theme-danger only for actions with serious consequences. .theme-uproot is uproot’s own purple.

Key classes: .btn-solid, .btn-outline, .btn-subtle, .btn-text, .btn .btn-link; combined with .theme-primary, .theme-accent, .theme-secondary, .theme-success, .theme-danger, .theme-warning, .theme-info, .theme-inverse, or .theme-uproot (uproot)

Sizes and states

Buttons come in four sizes. A disabled attribute grays a button out and makes it unclickable, for example until a participant has read something. A button with data-bs-toggle="button" switches between pressed and not pressed when clicked; give it aria-pressed="false", so that screen readers announce it as a toggle.

Key classes and attributes: .btn-lg, .btn-sm, .btn-xs, disabled, data-bs-toggle="button", aria-pressed

Buttons with icons

An icon before the label makes a button quicker to recognize. Icon-only buttons save space; .btn-icon makes them square. They need an aria-label (or a .visually-hidden text) so that screen readers can announce them.

Key classes: .btn-icon, .rounded-circle

Full-width buttons and alignment

On phones, large touch targets are easier to hit. Wrap buttons in .d-grid to make them full width; .md:d-flex with .md:justify-content-end turns them back into normal buttons on larger screens. To arrange uproot’s own Next and Back buttons, see the button_placement app (this walkthrough uses button_next(label=…) in Chapter.html).

Key classes: .d-grid, .gap-3, .md:d-flex, .md:justify-content-end, .w-100

Button groups and toolbars

A button group joins related buttons into one control. Give it role="group" and an aria-label. Several groups form a toolbar.

Key classes: .btn-group, .btn-group-vertical, .btn-group-sm, .btn-group-lg, .btn-toolbar

Toggle buttons

Radio buttons and checkboxes can look like buttons: put the <input> inside a <label> that has .btn-check and button classes. No id or for is needed. Radios in a .btn-group form a segmented control, which is a compact way to switch between views.

Key classes: .btn-check with a variant and a theme class, such as .btn-outline .theme-primary, on the label

Selected view: table

Tip. uproot only saves inputs that belong to a field defined in Python, so these toggles are not stored. To store a choice made with toggle buttons, define a field (e.g., a RadioField) and give the inputs its name. The last chapter does exactly that with cards. For the standard ways to ask questions, see the input_elements app.

The close button

.btn-close draws a neutral “×” in the color of the surrounding text, so it adapts to dark backgrounds by itself. Alerts, dialogs, toasts, and drawers use it to dismiss themselves. It has no text, so it always needs an aria-label.
